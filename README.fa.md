# پیکر | Peykar

پلتفرم مدل‌سازی و شبیه‌سازی زیستی با کد قابل مشاهده و مجوز استفادهٔ غیرتجاری.

پیکر مستقل از **همبون** است. همبون می‌تواند یک آزمایش درخواست کند؛ پیکر مدل مناسب،
محدودیت‌ها، اجرا و نتایج آن را مدیریت می‌کند. ارتباط از مسیر Instrument Adapter است.

[نقشهٔ کل پلتفرم](docs/roadmap.md) اکنون ۱۴ EPIC دارد و توسعه را به مدل چشم محدود
نمی‌کند. vCornea یکی از نمونه‌های اتصال است؛ سورس کامل کتابخانه‌های نام‌برده،
حل‌گرهای جداگانه و وابستگی‌های Git در [vendor](vendor/README.md) قرار دارند:
۲۵ مجموعهٔ منبع، ۵۲٬۱۶۷ فایل و ۳۷ وابستگی تکمیل‌شده، همراه با نام و مجوز اصلی.
مدیریت منبع، گراف زیستی پایدار و اجرای آزمایش چندمدلی نیز
به پشت‌صحنه اضافه شده‌اند. وضعیت سورس، محیط اجرا، اتصال نرم‌افزاری و شواهد زیستی
برای هر کتابخانه جداست؛ دریافت سورس به معنی نصب یا اعتبارسنجی مدل نیست.

[محیط‌های اجرایی](runtime_profiles/README.md) اکنون نصب و واقعاً آزمایش شده‌اند:
COPASI، NEURON، PhysiCell، PhysiBoSS، Chaste، VCell، GEARS و اجرای محاسباتی
مدل‌های PK-Sim/MoBi با OSPSuite، علاوه بر CompuCell3D/vCornea.
۱۱ رکورد اجرای واقعی از `/v1/runtimes` و `peykar runtimes list` قابل مشاهده است.
[عامل اجرای مستقل](docs/native-agent.md) اکنون مدل‌های SBML را با COPASI و PKML را
با OSPSuite از صف API اجرا می‌کند؛ ثبت مدل، لغو و دریافت خروجی واقعی قابل استفاده‌اند.
رابط گرافیکی ویندوزی، اتصال سایر موتورها به صف و اعتبارسنجی مستقل زیستی باز هستند.

[اجرای گروهی آزمایش‌ها](docs/epics/E2-reproducible-cohorts.md) نیز اضافه شده است:
پیمایش پارامتر، تکرار با seedهای مشخص، صف ترکیبی موتورهای عادی و native، لغو گروه
و گزارش آماری با نمایش اعضای ناموفق و چک‌سام خروجی هر اجرا.

[جریان چندمرحله‌ای native](docs/epics/E3-native-scalar-flows.md) نیز اضافه شده است:
خروجی واقعی هر مرحله با کنترل معنا، بافت زیستی و واحدها به ورودی مرحلهٔ بعد
منتقل می‌شود. برای ورودی غلظت SBML، نسخهٔ مشتق‌شدهٔ جدید و رسید تبدیل ثبت می‌شود؛
مدل اصلی و مجوز آن تغییر نمی‌کنند.

## این نسخه چه دارد؟

- سه بستهٔ مستقل برای قراردادها، موتورهای نمونه و پلتفرم.
- ثبت مدل و دیتاست با نسخهٔ ثابت و جلوگیری از تغییر همان نسخه.
- تعریف سناریو، شاخه‌سازی و مداخلهٔ زمان‌دار روی پارامترهای مجاز.
- صف پایدار و Worker مستقل با کنترل اجرای تکراری، لغو و قطع Worker.
- ثبت پارامترها، seed، نسخهٔ موتور و مشخصات محیط در Manifest هر اجرا.
- ذخیرهٔ خروجی با SHA-256 و بررسی خراب‌شدن یا تغییر فایل.
- API دارای توکن، CLI و قرارداد اتصال به همبون.
- کنترل واحد، معنای پورت، مقیاس و دستگاه مختصات پیش از اتصال مدل‌ها.
- بررسی عددی و مقایسه با داده، همراه با تفکیک دادهٔ مصنوعی از دادهٔ تجربی.
- اجرای موتور در فرایند فرزند با مهلت قطعی و محدودیت منابع در Linux.
- ورود CSV با حفظ فایل خام، واحدها، چک‌سام و سابقهٔ تبدیل.
- مجموعهٔ ارزیابی با نسخهٔ ثابت و گزارش متصل به اجرای مشخص و قابل بازیابی.
- تطبیق خروجی موتور با seed، زمان‌بندی و واحدها و بررسی محیط اجرا پیش از انتشار نتیجه.
- پذیرش آفلاین فایل‌های خارجی با بررسی SHA-256 فایل اصلی، وابستگی‌ها و runtime lock.
- واردکردن جدول خروجی با نگاشت صریح گام مونت‌کارلو به زمان و مقایسهٔ seedهای تکراری.
- ثبت پایدار و تغییرناپذیر شکاف‌های دانش با API دارای مجوز و فرمان‌های CLI.
- دریافت نسخهٔ ثابت و مجاز vCornea، محیط مستقل CompuCell3D 4.7.0 و اجرای واقعی با محدودیت منابع.
- ورود خروجی اصلی CSV و Parquet با حفظ ساعت، چهار نوع سلول، مختصات شبکه و سابقهٔ تبدیل.
- شش فایل مرجع منتشرشده، مقایسهٔ تکرار اجرای دو seed و اجرای ۶۰۰گامی عبور از زمان آسیب.
- تست، بررسی نوع‌ها، CI، Docker و مستندات معماری.
- فهرست پایدار کتابخانه‌ها با چک‌سام فایل‌ها، مجوزها و نسخهٔ جدیدِ وابستگی‌های تکمیل‌شده.
- اجرای اصلی Delta/Notch در مدل سلولی Chaste، خروجی PKML واقعی و خواندن دیتاست ۳۷٬۱۶۰ سلولی K562.
- ثبت نسخه‌دار روابط زیستی با منبع و جست‌وجوی همسایگی محدود از API.
- اجرای زنجیرهٔ مدل‌ها با انتقال خروجی نهایی به پارامتر آغازین مدل بعدی، کنترل واحد و معنا، لغو و ثبت سابقه.

## اجرا

با Linux، Python 3.12 یا 3.13 و uv:

```bash
uv sync --frozen --all-packages --group dev
uv run peykar demo
```

این دستور یک آزمایش ساده را از ثبت تا گزارش اجرا می‌کند. نیازی به API خارجی ندارد.
دو موتور نمونه، کاهش نمایی یک ماده و تغییر تصادفی جمعیت هستند. این‌ها برای تست
زیرساخت‌اند و مدل معتبر قرنیه یا اندام انسان معرفی نمی‌شوند.

## چه چیزهایی هنوز ساخته نشده‌اند؟

بازسازی کامل نتایج منتشرشدهٔ vCornea، شبیه‌سازی عمومی چندمقیاسی، داشبورد، یادگیری ماشین پیشرفته،
زیرساخت ابری و اعتبارسنجی تجربی مستقل، مراحل بعدی‌اند. برای هر کدام مرز ماژول،
پیش‌نیاز و معیار پذیرش نوشته شده است. پوشه‌های طراحی، پیاده‌سازی آماده معرفی نشده‌اند.

[EPIC E1](docs/epics/E1-vcornea-native-runtime.md) مسیر اجرایی اپراتور را کامل می‌کند؛
API شمارش سلول و سابقهٔ خروجی را ثبت و بازیابی می‌کند. اجرای کد خارجی دستور صریح
محلی است و وارد صف عمومی API نشده است. seed مرجع منتشرشده نامعلوم می‌ماند و
مقایسهٔ تکرار اجرا به معنی اعتبارسنجی زیستی مستقل نیست.

روی macOS یا Windows، دستور `make check-docker` تست‌های کامل Worker را در Linux
اجرا می‌کند و بسته‌ها را می‌سازد؛ volume دادهٔ سرویس‌های فعال به این تست متصل نمی‌شود.

## مجوز

مجوز فعلی `Peykar Noncommercial Source License 1.1.0` است: یک متن اختصاصی که
برای بازبینی حقوقی آماده شده است، نه یک مجوز استاندارد تأییدشده. مطالعه، پژوهش
و همکاری غیرتجاری با شروط آن مجاز است. فروش نرم‌افزار، سرویس پولی، API پولی،
کار مشاورهٔ پولی متکی به آن و استفاده برای توسعهٔ محصول تجاری، در مجوز عمومی
اجازه داده نشده‌اند. غیرانتفاعی بودن سازمان به‌تنهایی مجوز خدمات پولی نیست.

خدمات واقعاً بشردوستانه با ارائهٔ رایگان به دریافت‌کننده صریحاً مجاز است؛ کمک
اختیاری و حقوق معمول کارکنان به‌تنهایی مانع آن نیست. کمک مالی نباید شرط دسترسی
یا دریافت نتیجه باشد. بند 7A روشن می‌کند که مالک پروژه برای استفادهٔ شخصی،
پژوهشی یا تجاری از حقوقی که خودش مالکشان است، نیاز به خرید مجوز از خودش ندارد
و می‌تواند همان حقوق را با توافق جداگانه واگذار کند. این اختیار شامل حقوق
دیگران نمی‌شود؛ شخصیت حقوقی مستقل هم باید مبنای مالکیت یا مجوز مشخص داشته باشد.

چنین مجوزی در تعریف رسمی Open Source قرار نمی‌گیرد. فایل‌های `LICENSE` و
`LICENSING.md` متن و حدود دقیق را توضیح می‌دهند.

نسخهٔ خصوصی قبلی 0.1.0 متن Apache-2.0 داشت. اگر شخصی قبلاً حقوق معتبری تحت آن
گرفته باشد، تغییر فایل مجوز آن حقوق را پس نمی‌گیرد. این گفت‌وگو انتشار عمومی یا
تحویل به شخص ثالث را اثبات نمی‌کند. همچنین اضافه‌کردن مجوز، مالکیت و امکان
موفقیت در شکایت را خودکار اثبات نمی‌کند. متن اختصاصی، مالکیت و وضعیت حقوق
نسخهٔ قبلی باید پیش از انتشار عمومی یا اقدام حقوقی با وکیل نرم‌افزار بررسی شوند.
